# QuantumTest (repo: greenbook): rules for every session

QuantumTest (renamed from GreenBook → RainbowPrep → FreedomPrep → QuantumTest, owner request 27 Nov 2026, to match the domain quantumtest.xyz) is a free SAT practice website with a Bluebook-style test screen. Students pick the look of the site.
The repo, Supabase project, Vercel project and import format (`greenbook-import-1`) keep the old name; only what students see is QuantumTest. CSS hooks keep their `fp-`/`rp-` prefixes. The Google OAuth app is named "QuantumTest".

## Structure (built to change safely)
- `app/` routes only. A page file awaits params, calls a feature's query and renders a feature component. Keep it under ~30 lines.
- `features/<name>/` one sealed folder per feature: `components/`, `queries.ts`, `actions.ts`, `schema.ts`, `index.ts`, `README.md`.
  Other code imports a feature ONLY through `@/features/<name>` (its index.ts). ESLint enforces this.
- `core/` shared and feature-free: `design/` (tokens + ui), `layout/` (app shell), `config/` (subjects, feature switches), `scoring/`, `question/`, `db/`. `core/` must never import a feature.
- Add a feature = folder in `features/` + page in `app/(app)/[subject]/` + one line in `core/config/features.ts`.
- Hide a feature = `enabled: false` in `core/config/features.ts`. Unfinished work merges switched off.
- Subject facts (timing, modules, tools, domains) live in `core/config/subjects.ts`, never hard-coded.
- Database changes only through numbered files in `supabase/migrations/`. Add before you remove.
- Never send correct answers to the browser during a test. The server grades and keeps the clock.

## Premium web lessons (studied from inter-nation.uz, owner request 27 Nov 2026)
When the owner asks for "what you learned from those websites", or for a page to feel premium and not AI-made, apply these. Used so far on the home page only; inside the app stays as it is unless asked.
- One typeface for everything (they use Inter; ours is Inter via `fp-display`). Headlines heavy (700–800) and tight; body plain and grey. No font mixing.
- Few colors: white, soft grey cards (#f4f5f6 / #eff0f2 family), near-black (#141416), and ONE loud accent used sparingly (theirs is yellow #ffcf00 into orange). Accent goes on the main button and a word or two, nowhere else.
- Real proof over decoration: real photos (their building, teachers, branches), real artifacts (certificates, partner logos, an actual phone screenshot of the app), specific numbers. For us that means real product pieces (profile, score scale, bubbles, highlights) and facts computed from config. Never stock art, never invented stats.
- Layout: bento grid of rounded cards (16–28px corners) in mixed sizes with ONE dark card for contrast; floating pill-shaped menu bar; pill buttons, sometimes with a small icon; big quiet spacing between sections; dark full-width band for the key moment and the closing call.
- One playful object at most per screen (their glossy 3D shapes); everything else calm.
- Skip what dates them: all-capital section titles. Use big sentence-case headlines instead.

## Voice (owner request 27 Nov 2026)
- Words the student reads (headlines, subtitles, empty pages, notes) are short, bold, a little cold and mysterious: "Not another prep site." "Mistakes don’t leave." "Clean. Suspiciously clean." "Your move." Two to six words is ideal; no explaining paragraphs. A little arrogance is fine; never mean.
- Buttons and form labels stay plain and say what happens ("Start", "Log in", "Save colors"). Exam screens keep Bluebook's wording. Legal lines (College Board credit) stay as they are.
